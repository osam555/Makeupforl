## 1. 가장 큰 차이 — 이번 문항들은 잠겨 있다

앞선 5편은 무료 문항이라 답을 다 들려줘도 됐다. 이번 10개는 **유료 95개 안에 있다**.
처음 지시에도 「잠금 95개 답은 쇼츠에 넣지 않는다」가 있었다 — 허브 본문 규칙과 같은 이유로, 답을 다 주면 살 까닭이 없어진다.

그래서 한 편의 모양을 **질문 → 공감 → 답의 앞부분 → 결론 직전에 멈춤 → "답은 100문100답에서"** 로 한다.

- 답의 **앞쪽 자막 1~2개**(왜 그 고민이 생기는지, 무엇을 봐야 하는지)까지만 들려준다.
- **결론**(어떤 머리·어떤 색·며칠 전)은 말하지 않는다. 화면에는 잠금 화면(🔒 + 흐린 자막)을 보여 준다.
- 어디서 끊을지는 문항마다 자막(`cues`)을 읽고 정해 **원장님 결재(`/admin/proposals`)** 로 올린다.
  시드 JSON 의 잠금 답은 비어 있어 Firestore 에서 읽어야 한다.

## 2. 한 편의 구성 (약 35~45초)

| 시간 | 내용 | 도구 |
|---|---|---|
| 0–2초 | 훅 한 줄(큰 글씨) + 대표 사진 | HyperFrames |
| 2–8초 | 원장님이 질문을 받아 공감하는 한마디 — 예 「안경 쓰시는 혼주님, 정말 많이 물어보세요」 | **Flow** 8초 1클립 |
| 8–25초 | 답의 앞부분(원래 답 음성) + 사진 패널 / 채널 B롤 | Remotion(자막·패널) |
| 25–30초 | 결론 직전에 멈춤 → 잠금 화면 + 「정답은 100문 100답에서」 | HyperFrames |
| 30–35초 | 끝 카드 → 도메인 카드 + 「링크는 채널 프로필에 있어요」 | 기존 `ending()` |

- Flow 대사는 **답이 아니라 새로 쓴 공감 한 줄**이다. 답을 Flow 로 읽히지 않는다(잠금 답이 새 음성으로 퍼지는 것을 막고, 입 크기 문제도 8초 안에서 끝난다).
- 공감 대사 10줄도 결재에 같이 올린다.

## 4. 목소리와 입 — 앞선 소개 쇼츠에서 배운 것

- **목소리는 하나.** 답 음성(edge-tts)과 Flow 목소리가 섞이면 「원장 음성이 여러 개」가 된다.
  Flow 컷과 답 음성을 모두 `voice-first.wav` 음색으로 바꾼다(`flow_voice_convert.py`, 답 음성은 `--plain`).
- **입 크기:** 새 Flow 컷마다 `mouth_size.py` 로 재서 소개 쇼츠 ①(p90 0.102)의 1.3배를 넘으면 다시 만든다.
  해상도를 406×720 으로 맞춰 견준다.
- **립싱크:** Flow 가 낸 말 박자를 그대로 두고 음색만 바꾼다(늘이고 줄이기 금지).
- 워터마크는 잘라내고, 업로드 때 「AI 사용 — 예」로 표시한다.
