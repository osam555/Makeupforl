## 1. 누구에게, 무엇을

- **시청자**: 홈페이지는 있는데 문의가 안 오는 소규모 사업자(오일 판매·클래스·샵·전문직). Oilpage 가입 유도.
- **한 줄**: *홈페이지가 손님에게 세 가지만 물었고, 손님이 연락처를 남겼고, 결제가 됐다.*
- **왜 설문봇인가 (챗봇과 다른 점을 한 장면으로)**: 자유 입력 챗봇은 50~60대 손님이 키보드를 꺼내야 한다. 설문봇은 **탭 세 번**이고, 키보드는 마지막 이름·번호 칸에서만 나온다. 그래서 답이 끝까지 간다.
- **톤**: 자랑이 아니라 기록. 실제 화면과 실제 숫자.

## 3. 쇼츠 A 장면표 (45초)

설문봇 장면은 **실제 `/honjoo100#ask` 를 Playwright 로 녹화**한다(말풍선 "입력 중" 점 세 개, 0.7초 간격 등장까지 그대로). 손님 역의 탭은 스크립트로 누른다. 이름·번호 칸은 가짜 값("김○○ · 010-****-1234")을 넣고 제출은 **데모용 Firestore 가 아니면 하지 않는다** — 실제 접수함에 가짜가 들어가면 원장님 폰에 알림이 간다.

## 4. 본편에 붙는 60초 (Oilpage 장면표 1번 앞)

기존 Oilpage 본편은 "사장님, 같은 질문 오늘 몇 번 답하셨나요?" 로 시작한다. 그 앞에 쇼츠 A 의 0:03–0:36 을 16:9 로 조립해 **"먼저 결과부터"** 로 보여 주고, 원장님 15초 → "그래서 어떻게 만드냐면" → 기존 1번. Oilpage 데모 챗봇 장면(6번 "웹·카톡 같은 답")과 나란히 두어 **"물어보는 봇(챗봇)과 묻는 봇(설문봇), 둘 다 한 홈페이지에"** 를 한 줄로 정리한다. 요금 카드·엔드카드는 기존 그대로.

## 5. 만드는 순서 (Oilpage 틀 재사용, 비용 ≈ 0)

작업 폴더 `~/dev/aroma-chatbot-promo/`(build/gen.mjs·assets/fonts·audio/ 재사용).

1. **사실 수집** — 0절 표. 어드민 상담 화면·설문 통계·이용권 회원 화면에서 숫자만 뽑는다. 손님 이름·번호는 안 쓴다.
2. **실화면 녹화** — Playwright 1080×1920(폰) + 1920×1080(본편):
   - `/honjoo100#ask` 설문 흐름 — 로컬 `npm run dev` 에 `FIREBASE_SERVICE_ACCOUNT` **없이** 띄워 녹화하면 제출이 503 으로 막혀 실제 접수함을 더럽히지 않는다(CLAUDE.md 의 설계된 폴백). 제출 뒤 "잘 받았어요" 말풍선은 HyperFrames 로 덧그린다.
   - 어드민 상담 신청·이용권 회원 화면 — 실제 데이터는 가리고, 한 줄 슬라이드인은 HyperFrames.
   - youngliving.page 위젯 "몇 방울?" → 답 (본편 비교 컷).
3. **HyperFrames 장면** — `01-clock` 시계 · `02-overlay` 녹화 위 탭 하이라이트·자막 · `03-admin` 접수 한 줄 + 폰 잠금화면 알림 · `04-number` 카운트업 · `05-end` 엔드카드.
   자막 공통: 하단 1/4, 흰 글씨 + 검은 스트로크, 컷 경계 0.26초 페이드(`book/promo/영상제작-규칙.md` §6).
4. **내레이션** — 8줄 Typecast 지선(캐시 `hook_tts.typecast` 재사용). 24kHz/48kbps/모노.
5. **원장님 촬영** — `docs/video/README.md` §4 안내. whisper 로 받아써 가장 잘 말한 테이크.
6. **합치기** — ffmpeg. −14 LUFS, 1.5초 넘는 무음 없음.
7. **검수** — 숫자가 0절과 일치 / 손님 식별 정보 없음(이름·번호·날짜) / 마감·과장 표현 없음 / 영리빙 로고·제품 사진 없음.
8. **결재** — `/admin/proposals` 요청 → 원장님 확인 → 업로드.

## 5-1. 가편집 1차 (2026-11-02, 클라우드 세션에서)

`video/out/설문봇-쇼츠A-draft.mp4` — 40초, 무음. 만든 법은 `video/work/survey/` 에 그대로 있다:
- `record.mjs` — 로컬 dev(`npm run dev`, 서비스 계정 없음)를 상대로 `/honjoo100#ask` 를 540×960@2x 로 스크린샷 연속 촬영(약 5fps).
  Playwright 의 recordVideo 는 DSF>1 일 때 1배 화면을 구석에 그려 못 썼다. `/api/consult-lead` 는 가로채 200 을 돌려준다.
  글꼴 CDN(jsdelivr)이 막혀 Pretendard 를 로컬에서 덮어씌웠다(`fonts/` 는 npm `pretendard` 패키지에서 꺼냄, 커밋 안 함).
- `scenes.html` + `render-scenes.mjs` — 시계·어드민 접수 알림·숫자·엔드카드. HyperFrames 가 없어 같은 생각(HTML 한 장 = 장면)을 스크린샷으로.
- `assemble.sh` — 다섯 장면 concat + drawtext 자막(단계 시각은 `rec/steps.json`).
- 2차(같은 날): 녹화를 CDP 스크린캐스트로 바꿔 약 33fps(`--force-device-scale-factor=2` 가 있어야 1080×1920 이 나온다 —
  컨텍스트의 deviceScaleFactor 는 스크린캐스트가 무시한다). 글자 크기·테마 단추 숨김, 자막 0.26초 페이드, 끝 페이드아웃.
- **내레이션 7줄은 Sunra 에 만들어 두었다**(MiniMax TTS · Calm_Woman · 1.05배, 무료 일일 크레딧 7).
  프로젝트: https://sunra.ai/project/3ef48753-1310-4229-b72c-4146be9f3920 — 이 클라우드에서는 cdn.sunra.ai 가 막혀
  파일을 못 받았다. 맥에서 7개를 받아 `video/work/survey/tts/n1..n7.mp3` 로 두고 `assemble.sh` 에 오디오를 붙인다.
  (원래 8줄이던 "그리고 연락처를 남깁니다" 와 "아침에 사장님 폰에…" 는 한 줄로 합쳤다. Typecast 지선으로 다시 뽑아도 된다.)
- 3차(같은 날): 소리. `sfx/` 를 ffmpeg 로 합성 — 4화음 패드(C·Am·F·G, 저역만, 느린 떨림)가 받침, 밤·아침 알림 '띵' 2회,
  탭 클릭 4회(자막 시각과 같은 변수). `assemble.sh` 가 `tts/n1..n7.mp3` 가 있으면 장면 시각에 맞춰 자동으로 얹는다 —
  맥에서 Sunra 파일 7개를 그 이름으로 두고 `bash assemble.sh` 만 돌리면 된다. 음량 −15.8 LUFS, 피크 −1.3 dBFS.
- 4차(같은 날): 인트로를 훅으로 — 쇼츠는 첫 1초에 멈추게 해야 해서, 시계부터 보여 주던 것을 빼고 **결론 한 줄**("자는 동안 결제가 됐다.")을
  먼저 때린다. 숫자는 사실(1건·55,000원)뿐이라 과장은 아니다. 장면은 `scenes.html#hook`, 소리는 `sfx/thud·whoosh`. 전체 45초.
- **없는 것**: 내레이션 파일(위), 원장님 촬영 컷(엔드카드 앞), Flow 컷(`설문봇-쇼츠A-Flow-프롬프트.md`).

- 설문 녹화의 손님 답은 **연출**이고 자막에 "실제 화면, 손님 정보는 가상" 을 넣는다. 실제 접수 이름·번호·날짜는 어떤 형태로도 안 보인다(개인정보처리방침 2026-11-01 판과 같은 기준).
- 숫자는 0절에서 확인된 것만. "오늘 자정까지" 같은 마감 문구·비교·과장 금지(표시광고법, `Wed100ChatGuide` 주석).
- 원장님 얼굴·목소리는 실제 촬영본만.
- 어드민 화면에 다른 손님이 보이면 전부 가린다. 녹화는 실제 접수함에 쓰지 않는 환경에서만.
