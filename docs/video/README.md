> AI 생성 홍보영상(2026-09) 규칙은 따로 있다: `book/promo/영상제작-규칙.md`.

## 1. 결론 — 무엇으로 만드나

**원장님이 실제로 찍은 영상 + 자동 편집.** AI 로 원장님 얼굴을 만드는 길은 두 번 다 실패했다.

| 시도 | 결과 | 왜 안 됐나 |
|---|---|---|
| AI 생성 홍보영상 (Higgsfield nano-banana → kling, 2026-09-02~03) | 17초 1편(`book/promo/홍보영상_자막.mp4`) — 쓸 수 있는 컷이 절반 | 컷마다 인물이 바뀜(혼주가 다른 사람, 안경 생김), 여러 명·전신이 같이 나옴 → 규칙을 만들어 겨우 맞춤 |
| Google Flow(Veo)에 원장님 사진·영상을 넣어 생성 | 실패 | Veo 는 컷마다 **새 사람**을 그린다 — 참고 이미지 3장으로는 「닮은 사람」까지. 대본 입 모양도 못 맞춤 |
| HeyGen 아바타 | 미달 (사용자 판단, 2026-10) | 「원장님 같지 않은」 얼굴·목소리 |

메이크업은 **신뢰**가 핵심이라 실제 원장님 얼굴·목소리가 가장 낫고, 실제 촬영이면 일관성 문제가 아예 없다.

## 3. 폴더 (영상 파일은 git 에 안 올린다)
```
video/
  raw/        원장님 원본 영상(폰 촬영·채널 원본)      ← .gitignore
  scripts/    대본(.md/.txt) — 커밋
  work/       자막·컷 목록·중간 파일                    ← .gitignore
  out/        완성본                                    ← .gitignore (올린 뒤 드라이브 보관)
  uploaded.json  올린 기록(영상 ID·날짜) — 커밋
```

## 4. 원장님께 보낼 촬영 안내 (한 장)
1. **세로**로, 폰을 눈높이에 고정(삼각대·책 위). 가슴 위까지 나오게.
2. 창을 **마주 보고** 앉는다(창을 등지면 얼굴이 어둡다).
3. 프롬프터 앱에 대본을 넣고 읽는다 — 틀리면 **멈추지 말고 그 문장부터 다시** 말하면 된다(나중에 자동으로 잘 된 쪽만 남긴다).
4. 조용한 곳. 가능하면 **핀마이크**(유선/무선, 수만 원대)를 옷깃에.
5. 한 번에 10~20분, 대본 여러 개를 이어서 찍어도 된다. 끝나면 **원본 화질 그대로**(에어드롭·구글 드라이브, 카톡은 「원본 보내기」)로 보내 주세요.

## 5. 만드는 순서 (자동 편집 — 비용 거의 0)

재사용 가능한 도구는 범용 키트로 만든다 → **전역 스킬 `talking-head`(예정)**. 이 저장소에는 원장님 자료와 결과만 둔다.

## 6. 다른 맥에서 이어서 할 일
1. `git clone https://github.com/osam555/Makeupforl.git` (또는 `git pull`) → 이 파일
2. 도구: `brew install ffmpeg node openai-whisper yt-dlp` (whisper 첫 실행 때 모델을 받는다)
3. 원장님 원본을 `video/raw/` 에, 대본을 `video/scripts/` 에
4. Claude Code 에게: 「docs/video/README.md 읽고 원장님 영상 만들자 — 먼저 talking-head 키트를 만들고 롱폼 1편을 쇼츠로 잘라 보자」
5. 첫 결과물은 **올리기 전에 원장님 확인**(결재 → `/admin/proposals` 에 요청으로 올려도 됨). 업로드는 원장님 채널이므로 원장님 계정에서.

## 7. 지킬 것
- 원장님 얼굴·목소리를 AI 로 새로 만들지 않는다(1절). 실제 영상만 자르고 꾸민다.
- 효과·시술 결과 과장 금지, 「보톡스」 등 시술 관련은 원장님 말 그대로만(의료 광고 아님 — 메이크업 정보로).
- 손님 사진(B롤)은 **동의 받은 것만**. 혼주·하객 얼굴이 나오는 행사 영상은 원장님께 확인.
- 이 작업 내용은 makeupforl 안에만 둔다(사이트 매니저의 다른 프로젝트 위키에는 일반 절차만, 원장님 자료는 넣지 않는다).
