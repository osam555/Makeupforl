## 손님 화면은 이미 안전한 길로 다닌다

- 문항 페이지·허브·사이트맵·칼럼은 모두 **서버에서** `getWed100Items()` 로 읽는다. 운영(Vercel)에서는 Admin SDK 가 읽으므로 보안 규칙의 영향을 받지 않는다.
- 잠긴 페이지 HTML 에는 `teaser()`(95자)만 실린다. 구매자는 `/api/wed100/answer`(로그인 + 명단 확인) 로 본문을 따로 받는다.
- 브라우저가 클라이언트 SDK 로 `wed100_questions` 를 읽는 곳은 **어드민 편집기 한 곳**뿐이고, 관리자로 로그인한 상태에서 읽는다.

그래서 새 컬렉션을 따로 만들거나 문서를 둘로 쪼갤 필요가 없다. **읽기 문만 관리자에게로 좁히고, 공개 시드에서 잠긴 답을 빼면 된다.**

## 바꿀 것

### A. Firestore 규칙 — `firebase/firestore.rules`
- `wed100_questions`: `allow read: if isAdmin();` (쓰기는 그대로)
- `site_config/wed100`: 문서는 공개 읽기 그대로 두고, 옛 `members` 필드를 **비운다**(아래 E). 규칙으로 필드만 막을 수는 없다.
- 영향: 서버(Admin SDK)·어드민 편집기(관리자 로그인)는 그대로. 서비스 계정이 없는 로컬 개발은 2단계(클라이언트 SDK)가 권한 오류 → 시드로 폴백(이미 있는 길).

### B. 공개 시드에서 잠긴 답 빼기 — `scripts/wed100/sync_seed.py`, `src/data/wed100.json`, `src/types/wed100.ts`
- 시드를 만들 때 `site_config/wed100.freeQna` 를 읽어, 무료가 아닌 문항은 `answer` 를 `teaser()` 와 같은 95자 한 덩이로, `cues`·`audio` 는 비우고, `sealed: true` 를 붙인다. 질문·질문 음성·사진·키워드는 그대로(이미 공개된 것들).
- 잠긴 답의 원본은 Firestore 와 `wed100_versions`(관리자 전용)에 있다. 저장소에는 두지 않는다.

### C. 시드가 비었을 때도 규칙이 깨지지 않게 — `src/lib/wed100.ts`, `src/app/honjoo100/[slug]/page.tsx`, `src/app/api/wed100/answer/route.ts`
- **「Firestore 우선 · 시드 폴백」 그대로**: 읽는 순서는 바꾸지 않는다. Firestore 가 안 될 때 화면이 비지 않고 시드가 뜬다.
- **「설정을 못 읽으면 잠그지 않는다」 그대로**: 잠금 판단(`isOpen`)은 손대지 않는다. 다만 시드로 폴백했는데 그 문항이 `sealed` 라면 **보여 줄 본문 자체가 없으므로** 잠긴 화면(티저 + 안내)을 그린다. 이건 잠근 게 아니라 원고를 못 가져온 것이다 — 95자를 "전체 답" 인 척 보여 주면 더 나쁘다.
- 같은 이유로 `/api/wed100/answer` 는 `sealed` 문항이면 "잠시 뒤 다시" 로 503 을 돌려준다(구매자에게 빈 본문을 주지 않게).

### D. 어드민 JS 에서 시드 빼기 — `src/app/admin/wed100/Wed100Admin.tsx`, `src/app/admin/dashboard/page.tsx`
- 클라이언트 컴포넌트의 `import seedRaw from '@/data/wed100.json'` 을 없앤다. 편집기의 "시드로 보기"는 서버 페이지(`page.tsx`)가 시드를 넘겨 주거나 제목만 담은 가벼운 목록으로 바꾼다. B 를 하면 새는 내용은 없어지지만, 102문항 JSON 이 JS 에 실리는 것 자체가 무겁고 다음에 또 샌다.
- `/api/wed100/save` 의 `action: 'seed'`(시드 → Firestore 덮어쓰기)는 `sealed` 문항의 `answer`·`cues`·`audio` 를 **덮어쓰지 않게** 막는다. 안 막으면 단추 한 번에 잠긴 답 95개가 95자 티저로 바뀐다.

### E. 구매자 이메일 치우기 — 일회성 스크립트 `scripts/wed100/move_public_members.py` (새로 만듦)
- `site_config/wed100.members` 의 2건을 `wed100_members` 로 옮기고(이미 있으면 건너뜀) 필드를 지운다. `getWed100Access()` 는 두 곳을 합쳐 보므로 구매자가 막히지 않는다.

### F. 음성 — `firebase/storage.rules`, 일회성 스크립트 `scripts/wed100/rotate_audio_tokens.py` (새로 만듦)
- `wed100/audio/{file}`: `allow read: if isAdmin();` → 토큰 없는 주소로 받는 길이 막힌다. 화면이 쓰는 주소는 모두 `?token=` 이 붙은 다운로드 주소라 **규칙과 상관없이 계속 재생된다**(무료 문항·질문 음성 포함).
- 하지만 그 토큰 주소들이 이미 공개 저장소·옛 JS 에 나가 있으므로, **잠긴 문항의 답변 음성만 토큰을 새로 발급**하고 Firestore `audio` 를 새 주소로 바꾼다. 옛 주소는 그 순간부터 403. 구매자는 `/api/wed100/answer` 로 새 주소를 받는다.

## 사람이 해야 하는 것 (코드로 못 하는 것)

1. **규칙 배포**: `firebase deploy --only firestore:rules,storage` — 아래 순서 지킬 것.
2. **저장소 공개 여부 결정**: GitHub 이력에 잠긴 답 전문이 2026-08-05 부터 남아 있다. 시드에서 빼도 옛 커밋으로 읽힌다. 저장소를 **비공개로 돌리는 것**을 권한다(Vercel 배포는 비공개 저장소에서도 그대로 된다). 이력 다시 쓰기(force-push)는 권하지 않는다 — 이미 받아 간 사본은 못 지우고 위험만 크다.
3. 이미 밖으로 나간 **글은 되돌릴 수 없다.** 위 작업은 앞으로 새는 것을 막는 일이다. 음성은 F 로 옛 주소를 죽일 수 있다.

## 순서

1. 코드(B·C·D) 배포 — 시드가 비어도 화면이 맞게 도는 것을 먼저 올린다.
2. E 스크립트로 구매자 이메일 이동 → 어드민 회원 화면에서 2명 확인.
3. 규칙 배포(A·F 규칙).
4. F 스크립트로 잠긴 음성 토큰 교체 → 구매자 계정으로 잠긴 문항 하나 재생 확인.
5. 확인: 로그인 없이 `…/documents/wed100_questions/p4-01` → 403, 운영 `/admin/wed100` JS 에 답 문장 없음, 토큰 없는 음성 주소 → 403, 무료 문항 재생 정상.
